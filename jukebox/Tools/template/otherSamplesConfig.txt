<NAME>Dynamic lookup OO
<DESC>Sorting is on first field. 
To manipulate the lookup query object add the callback procedure hook "myLookupObject" 
(probably use "WHERE false" as the initial query in this case).
To create a lookup button for a field use the clipboard conversion tool.
"<myProcName>" here should typically correspond to the procedure created from adding a tool to the toolbar

<CODE>
PROCEDURE <myProcName>:
  JBoxServerAPI:Instance:Lookup("<table>"
                    + ";<field1>"
                    + ";<field2>"
                   ,"WHERE true"
                   ,"<field1>,<field2>"   /* <- return values for these fields */
                    ).

  IF JBoxServerAPI:Instance:LookupOk THEN DO:
    ASSIGN <field1>:SCREEN-VALUE = JBoxServerAPI:Instance:LookupValue(<field1>)
           .

    APPLY "any-printable" TO <field1>.
  END.
  
<NAME>Dynamic lookup
<DESC>Sorting is on first field. You can change a lot by using the setLookupAttributes hook.
To create a lookup button for a field use the clipboard conversion tool.
See also the winsrc\samples\DynLookupUsage.w
"<myProcName>" here should typically correspond to the procedure created from adding a tool to the toolbar

<CODE>
PROCEDURE <myProcName>:
  DEF VAR cReturnValues   AS CHAR NO-UNDO.
  DEF VAR bOk             AS LOG  NO-UNDO.

  /* See also call-back procedure setLookupAttributes */

  THIS-PROCEDURE:CURRENT-WINDOW:SENSITIVE = FALSE.
  RUN JBoxLookup.w (THIS-PROCEDURE,50,
                    "Customer"
                    + ";Custnum"
                    + ";Name"
                   ,"WHERE false"
                    ,""                                                  
                    ,"CustNum,Name",   /* <- return (pipe-separated) values for these fields */
                      OUTPUT cReturnValues,
                      OUTPUT bOK).
  THIS-PROCEDURE:CURRENT-WINDOW:SENSITIVE = TRUE.

  IF bOk AND cReturnValues NE "" THEN DO:
    JBoxServerApi:
  END.
            
  THIS-PROCEDURE:CURRENT-WINDOW:MOVE-TO-TOP().

<NAME>Browse for static TEMP-TABLE
<DESC>
To build a dynamic browse for a TEMP-TABLE defined on the client follow these steps:

1: Draw a RECTANGLE placehoder for the browse
2: Add the code under
3: (Probably best to) move the definition of the variable that holds the browse object (here oBrowse) to DEFINITIONS
4: Optionally limit visible fields by setting the buffersAndFields attribute                         

<CODE>
PROCEDURE InitializeObject: 

DEF VAR oBrowse AS JBoxBrowse NO-UNDO.

  oBrowse = NEW JBoxBrowse(brwTtCustomer:HANDLE,      /* handle to place-holder rectangle */
                           YES,                       /* multiple-select? */ 
                           "",                        /* title */
                           NO,                        /* row-markers (if multiple) */
                           BUFFER ttCustomer:HANDLE). /* The BUFFER ttCust.. parameter tells the browse that it is a local temp-table */
  
  oBrowse:buffersAndFields = "ttCustomer;name;custNum". /* Visible fields - optional setting */


<NAME>Calculated field in dynamic query/browse 
<DESC>
There are 3 ways to use parameters for the procedure name:

1.    None, ie procedure-name: The parameters for the procedure are (still):

DEF INPUT  PARAM irBuffer              AS ROWID    NO-UNDO.
DEF INPUT  PARAM icSessionId           AS CHAR     NO-UNDO.
DEF OUTPUT PARAM ocValue               AS CHAR     NO-UNDO.

Sample definition of field in browse or query:
"+OrderCount|INTEGER|>>>>9|order_count[.p]|OrderCnt"

Template: server\template\calc_field.p

2.    Rowid, ie procedure-name(ROWID). This allows for an additional parameter to be invoked either by using the calcParam<field-name> attribute for browsers or queries or by adding the parameter value directly to the field specification (see the getFieldList Server API). Procedure parameters:

DEF INPUT  PARAM irBuffer              AS ROWID    NO-UNDO.
DEF INPUT  PARAM icParam               AS CHAR     NO-UNDO.
DEF INPUT  PARAM icSessionId           AS CHAR     NO-UNDO.
DEF OUTPUT PARAM ocValue               AS CHAR     NO-UNDO.

Sample definition of field in browse or query:
"+OrderCount|INTEGER|>>>>9|order_count[.p](ROWID)|OrderCnt"

Sample definition for using parameter with getTempTableJoin Server API function:
"+OrderCount|INTEGER|>>>>9|order_count[.p](ROWIDnnnn)|OrderCnt"
nnnn: Parameter value

Sample definition for using parameter with getFieldList Server API function:
"+OrderCount|order_count.p(ROWIDnnnn)"
nnnn: Parameter value

Template: server\template\calc_field_with_dyn_client_input_param.p

3.   Fieldname, ie procedure-name(CustNum). A more generic way allowing reuse of the procedure for multiple buffers. The datatype for the input param will now vary:

DEF INPUT  PARAM iiCustNum             AS INT      NO-UNDO.
DEF INPUT  PARAM icSessionId           AS CHAR     NO-UNDO.
DEF OUTPUT PARAM ocValue               AS CHAR     NO-UNDO.

Sample definition of field in browse or query:
"+OrderCount|INTEGER|>>>>9|order_count[.p](CustNum)|OrderCnt"


";+OrderTotal|DECIMAL|->><>>><>>9.99|CustOrderTotal(CustNum)|Order Total"

<CODE>
PROCEDURE SumSelectedRecord: 
DEF VAR hMenuItem     AS HANDLE NO-UNDO.
DEF VAR fTotal        AS DEC NO-UNDO FORMAT "->>>,>>>,>>9.99".
DEF VAR iCount        AS INT NO-UNDO.
DEF VAR cTotalLabels  AS CHAR NO-UNDO INIT "Amount,Balance".
DEF VAR cTotalFields  AS CHAR NO-UNDO INIT "AccountAmount,AccountBalance".
DEF VAR ix            AS INT NO-UNDO.

hMenuItem = JBoxSession:Instance:CurrentWidget.

DO ix = 1 TO oBrwKonto:BROWSE-HANDLE:NUM-SELECTED-ROWS:
  IF oBrwKonto:BROWSE-HANDLE:FETCH-SELECTED-ROW(ix) THEN
    ASSIGN fTotal = fTotal + oBrwKonto:BUFFER-HANDLE:BUFFER-FIELD(ENTRY(LOOKUP(hMenuItem:LABEL,cTotalLabels),cTotalFields)):BUFFER-VALUE
           iCount = iCount + 1.

<NAME>Extent fields in fieldMap object
<DESC>
Extents are automatically converted to calculated fields in the query and local temp-table specification 
but to be able to do automatic update of these columns you need to specify the mapping between the database-field and input-field.

So, for f.ex to update the MonthQuota field(s) in Sports2000.Salesrep you assign the mapping by setting the updateFields property of the fieldMap like this:

oFmSalesRep:updateFields = "repname,MonthQuota[1];MonthQuota_1,MonthQuota[2];MonthQuota_2,..

MonthQuota[1] being the database field name and MonthQuota_1 is the input field
